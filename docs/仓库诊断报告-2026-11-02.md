## 一、一句话结论

不是项目做得差，而是「发现」和「上手」两个环节都断了。
项目本身有真东西（垂直教研语料、可用的 RAG + 多模态链路、国风 UI），但对外是一个「陌生开发者打不开、目标老师找不到」的状态。

## 三、为什么「没有人用」：五个根因

### 1. 零分发（决定性因素，占 80%）
仓库 8-23 创建、8-25 推完就停，之后没有任何提交。同时没有在 V2EX、掘金、知乎、小红书、B 站、公众号、教师群做过一次曝光。
GitHub 不会给一个 1 star 的中文小众项目自然流量，「做好就会有人来」在开源里从来不成立。**入口为 0，转化率再高也是 0。**

### 2. 受众与渠道错位
README 写的读者是「小学语文教师 / 班主任」，但：
- 老师不上 GitHub，也不会 `git clone` + 配置 4 个 API Key；
- 开发者会来，但看到的是「为某个具体老师定制的个人工作台」，找不到可以复用的价值。

结果两头都接不住。仓库现在同时得罪了两类人，谁都不会 star。

### 3. 上手门槛过高
从「点开链接」到「看到界面有效果」，需要：克隆 → venv → pip install → 申请 4 个 Key（DeepSeek、智谱、千问 DashScope、和风天气）→ 填 Key → 跑 seed_docs → 启动 uvicorn。生产部署还要 Nginx 子路径 + systemd。
没有 Docker、没有在线 Demo、没有演示视频、没有「不填 Key 也能看」的降级模式。
陌生人的耐心窗口大约是 1 分钟，你要求他做 15 分钟的事。

### 4. 定位是「六合一」，不是「解决一个问题」
收集箱 + 阅读 + 日程 + AI 对话 + 多模态 + 教学工具 + PPT，六个场景并列。
- 对老师：学习成本高，不知道该从哪用起；
- 对开发者：像 feature dump，看不出主线。

缺一句能被人转述的卖点，例如「上传一篇课文，出 30 页能直接上课的国风 PPT」或「拍照批改作文，给出评语」。没有这句话，别人无法替你传播。

### 5. 缺信任信号
无 LICENSE、无 Release、无测试、无 CI、无真实使用者反馈，star = 1。后来者看到这些会直接拿「1 star」当结论，不再看内容。这是一个自我强化的负循环。

## 五、两条路线，不要混着走

### 路线 A：要真实用户（唯一核心指标 = 首次跑通率）

必做三件事：
1. `docker compose up` 一键启动，并内置 mock 模式：不填任何 Key 也能打开完整界面、看到示例教案和示例对话。
2. 部署一个公开 Demo（学生机 + 域名即可，注意先解决 P0-2 的鉴权问题，否则会被刷爆）。
3. README 第一行：Demo 链接 + 90 秒 GIF/视频 + 一句话卖点。

只做一个场景做深（二选一）：
- 作文/作业拍照批改（多模态 + 评语）
- 上传课文 → 生成可直接上课的教案或 PPT

其余四个模块先收进「更多功能」，不要放在首屏。

分发渠道（分开写，别用同一份文案）：
- 老师侧：小红书、视频号/B 站（「我怎么用 AI 改 40 本作文」这类实操内容）、教师微信群、公众号投稿、区县教研员
- 开发者侧：掘金、V2EX、即刻（「在 2 核 2G 上跑 LangGraph + FAISS 的 RAG」这类技术内容）
- 找 5 位真实老师试用，把原话反馈贴进 README 的「使用者反馈」段落

### 路线 B：要面试作品集（用户数不是评判标准）

把叙事从「一个没人用的产品」改成「面向教育场景的垂直 RAG 参考实现」——这样受众变成开发者，star 和复用才有基础。

- 首屏换成可量化结果：检索命中率、相对无 RAG 的 Token 降幅、P95 延迟、单次生成成本
- 一张架构图 + 与基线（纯 prompt 直出 / Dify 搭建）的对比表
- 补齐 LICENSE、topics（`rag` `langgraph` `fastapi` `faiss` `education` `llm` `multimodal`）、Release v2.4.0、置顶「使用反馈」Issue
- 把 `docs/VibeCoding-Journey.md`（44 KB）拆成 3 篇技术文章发到掘金/知乎

## 七、写进简历/面试时可以怎么说

- 不要讲「这是一个给小学老师用的 AI 工作台」——这句话会被追问「有用户吗」。
- 改成讲「我在 2 核 2G 上实现了一套教育垂直领域的 RAG 系统，把检索命中率从 X 提到 Y，把单次生成 Token 成本降了 Z%，并把 PPT 生成做到了讲者备注自动写入 PPTX」。
- 个人项目不需要用户数，但需要一个**能复述的量化指标**。现在仓库里 Token 降幅、缓存命中、阈值过滤这些优化都已经做了，只是没有被量化表达出来——这是最容易补、收益最高的一块。
